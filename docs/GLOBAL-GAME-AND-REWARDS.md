# Global game, wagering, loyalty, and referrals — implementation gates

## Current state

HeroBet is still a play-money browser prototype. `web/src/game.js` generates and settles rounds in each browser, and `demoPlayers/{uid}` is client-writable. The bottom-nav Home tab now opens a player lobby, but the lobby clearly reports that rounds are not shared. No browser-side or Firestore-only workaround can safely turn that game into real-money betting: a player can alter client code, balances, round results, or cashout timing.

There is no betting API, scheduled worker, Cloud Functions service, Admin SDK, verified payment provider, or production license/operational configuration in this repository. So real wagers, payouts, shared always-on rounds, loyalty credits, and referral commissions remain disabled. The zero-NGN wallet and manual bank-transfer screens do not fund or settle the game.

## Required server design before enabling money

1. **Always-on, common rounds.** Run a server-owned round coordinator on a managed worker/scheduler. Store each round's server start time, betting close time, phase, and immutable result in a trusted database. Browser clients subscribe/read state only. Derive displayed multiplier from server timestamps so reloads and offline players do not stop or restart a flight. A single server result is used for every player in a round.
2. **Authoritative betting and cashout.** Accept, reject, cancel, and cash out through authenticated server endpoints. Perform wallet reservation/debit, bet creation, and idempotency-key recording transactionally. The server decides whether an action arrived before the bet cutoff or crash; client clocks are informational only. Settle every accepted bet once, including when the player is offline.
3. **Ledger, not editable balances.** Keep append-only, double-entry NGN entries for deposits, reserved stakes, losses, payouts, reward accruals, withdrawals, and reversals. A displayed balance is derived or transactionally reconciled from the ledger. Browser clients must not write wallet balances, bet status, round outcome, or reward credits.
4. **Loyalty target.** Accrue exactly `eligible_settled_stake × 0.0001` (0.01%) for each qualifying settled wager. Define eligible stake, void/refund handling, currency/rounding, minimum redemption, and whether the rate can change before launch. Accrual is server-side, idempotent, and separately journaled. Do not award from demo balance, pending bets, deposits, or a browser-calculated amount.
5. **Referral target.** Bind one upline referral to an account at registration using a validated, immutable referral code. Accrue one-level commission of `eligible_settled_downline_stake × 0.0001` (0.01%) for each qualifying settled wager; do not calculate it from deposits or unpaid/pending bets. Define anti-self-referral, abuse/fraud review, reversals, payout eligibility, and privacy rules. A referral credit must be posted as a distinct ledger event, once per settled bet.
6. **Safety, compliance, and operations.** Before real-money launch, obtain the relevant gambling/payment authorization for launch markets, age/KYC and AML checks, responsible-play controls, limits/self-exclusion, geofencing, fraud monitoring, dispute/support processes, independent game-fairness review, incident response, and reconciliation. Keep an auditable operator/admin trail. Do not advertise cash value or accept gameplay deposits before these controls and jurisdictional approvals are live.
7. **Security and release gate.** Move privileged writes to a trusted backend with server credentials; deny all browser writes to round, wager, settlement, ledger, wallet balance, loyalty, and referral records in Firestore rules. Add emulator/integration tests for concurrency, retries, cutoff races, duplicate settlement, offline-round continuation, balance invariants, and referral/reward idempotency. Deploy and verify rules and backend separately before changing UI status from unavailable.

The requested rates are represented in the lobby as target rates only. This document is a requirements checklist, not a betting implementation or compliance/legal advice.
